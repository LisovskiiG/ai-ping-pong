# 🟢 AI Ping-Pong

**Two AI models. One workspace. Unlimited perspectives.**

**AI Ping-Pong** is a web-based multi-model AI collaboration platform that enables users to interact with two large language models simultaneously, compare their responses, and initiate structured cross-model evaluations.

<img width="1394" height="981" alt="4_1" src="https://github.com/user-attachments/assets/82b87a16-96b7-4d7d-96e9-ecc50ac82fca" />


Unlike conventional AI chat interfaces, AI Ping-Pong introduces a human-directed collaboration workflow: users control when, how, and in which direction one AI model evaluates, critiques, analyzes, or summarizes another model's output.

The platform combines parallel AI processing, interactive model-to-model communication, configurable instructions, and session management within a unified workspace.

Designed for deployment on a Virtual Private Server (VPS), AI Ping-Pong runs as a containerized web application accessible through any modern browser.

## Key Features

### Parallel AI Processing

A single user request is dispatched simultaneously to two independently configured AI models.

Each model generates its response independently, and the results appear in separate, side-by-side panels.

The interface provides:

- Independent response streaming.
- Real-time model execution status.
- Response time measurement with 0.1-second precision.
- Side-by-side comparison of model outputs.
- Independent selection of Model A and Model B.

The platform supports integration with external LLM providers through configurable API adapters, including DeepSeek and OpenAI-compatible endpoints.

### Human-Controlled Cross-Model Collaboration

AI Ping-Pong implements a distinctive interaction mechanism based on manually controlled message forwarding.

Users can initiate evaluations in either direction:

**Model A → Model B**

The output generated by Model A is forwarded to Model B for further processing.

**Model B → Model A**

The output generated by Model B is forwarded to Model A.

Every transfer preserves the original user request and the relevant conversation context.

Unlike autonomous multi-agent systems, AI Ping-Pong places the user in full control of the interaction sequence.

Users decide which model evaluates another model's response, select the evaluation method, and determine when the collaboration is complete.

### Four Cross-Model Processing Modes

AI Ping-Pong provides four configurable processing modes:

**Review**

The receiving model critically examines another model's response, identifies potential inaccuracies, weaknesses, omissions, and logical inconsistencies, and suggests improvements.

**Analysis**

The receiving model performs a deeper examination of the submitted response, exploring its reasoning, assumptions, alternatives, and implications.

**Summary**

The receiving model produces a structured summary that extracts the essential points, conclusions, and relevant information from the original response.

**Custom Prompt**

Users define their own processing instructions through a dedicated prompt editor.

This mode enables customized evaluation workflows, specialized reviews, alternative interpretations, and domain-specific analytical tasks.

### Flexible Model Configuration

AI Ping-Pong provides independent model selection for both processing panels.

Users can configure:

- Model A provider and model.
- Model B provider and model.
- API connection settings.
- System-level instructions.
- External context and supplementary resources.

The architecture separates provider-specific API communication from the core application logic, making it possible to integrate additional compatible models without redesigning the interface.

### Context and System Prompt Management

The Settings interface provides tools for configuring the context supplied to AI models.

**Add File or Image** — Attach documents or images to provide additional information for model processing, subject to the selected model's supported capabilities.

**Add Link** — Supply external resources for contextual analysis through the application's resource-processing layer.

**System Prompt** — Define persistent behavioral instructions that influence how models interpret requests and generate responses.

These capabilities support specialized workflows for research, software development, technical analysis, documentation, and decision support.

### Session Management

AI Ping-Pong maintains structured interaction histories that include:

- Original user requests.
- Independent model responses.
- Cross-model message transfers.
- Selected processing modes.
- Model-generated evaluations.
- Response timing information.
- Session configuration and relevant context.

Users can create new requests and navigate previously saved sessions through the sidebar.

The conversation structure preserves the sequence of model interactions, supporting transparent review of how responses evolve through successive evaluations.

## System Architecture

AI Ping-Pong follows a modular client-server architecture optimized for containerized deployment.

### Frontend

**React · TypeScript · Tailwind CSS · Vite**

The frontend delivers a responsive browser-based interface with two independent AI response panels, model selectors, processing controls, session navigation, and contextual settings.

Its component-based architecture separates presentation logic from backend operations.

The interface communicates with the application server through HTTP APIs and receives streamed model output through Server-Sent Events (SSE).

### Backend

**Python · FastAPI · AsyncIO**

The backend coordinates all application operations, including:

- User request processing.
- Parallel LLM API calls.
- Cross-model message forwarding.
- Conversation context management.
- Processing mode execution.
- Streaming response delivery.
- Session persistence.
- Provider configuration.
- API authentication and credential access.
- Error handling, request limits, and execution timeouts.

Asynchronous processing allows both models to operate concurrently without blocking one another.

### LLM Integration Layer

The LLM integration layer provides a unified interface for external model providers.

Each provider adapter handles authentication, request formatting, response parsing, streaming, and provider-specific behavior.

The application communicates with AI models through their official HTTP APIs.

Requests are processed independently for each model, while cross-model interactions are coordinated by the backend.

**AI Ping-Pong does not require direct network communication between AI providers.** The application orchestrates all interactions and manages the exchange of model-generated content.

### Data Persistence

**SQLite · Persistent Docker Volumes**

Application data and session history are stored using persistent storage independent of the application container lifecycle.

This architecture allows application updates and container replacement without losing stored conversations and configuration data.

## Security and API Key Management

AI Ping-Pong is designed around server-side credential handling and separation of private information from browser-accessible application code.

API keys are not embedded in frontend JavaScript, HTML files, or public Docker images.

The deployment architecture uses runtime secrets supplied through Docker Compose Secrets or a compatible external secret-management system.

For user-managed credentials, the server-side credential layer uses encrypted persistent storage and controlled access.

Security measures include:

- Server-side API authentication.
- Secret isolation from frontend code.
- HTTPS/TLS encryption.
- Restricted access to credential-management operations.
- Encrypted storage of persistent private credentials.
- Separation of application configuration and sensitive secrets.
- Protection against accidental exposure of credentials in logs.
- Request validation and resource limits.
- Configurable provider access policies.

The browser communicates only with the application backend. External LLM API requests are initiated by the backend using authorized credentials.

For internet-accessible deployments, access control and authentication protect the application and its administrative functionality.

## Processing Workflow

1. The user selects Model A and Model B.
2. A request is submitted through the shared input field.
3. The backend dispatches the request to both models concurrently.
4. Responses are streamed into their respective interface panels.
5. The user selects Review, Analysis, Summary, or Custom Prompt.
6. A directional arrow forwards the selected model output to the other model.
7. The receiving model processes the forwarded content with the original request context.
8. The resulting response is added to the appropriate conversation history.
9. The user continues the interaction or starts a new session.

The workflow supports repeated, bidirectional evaluation without requiring autonomous model-to-model negotiation.

## Use Cases

AI Ping-Pong supports a wide range of professional and research-oriented applications:

- **AI response validation:** Compare independently generated answers and request critical evaluation.
- **Research assistance:** Examine complex subjects from multiple model perspectives.
- **Software development:** Review proposed architectures, programming solutions, and generated code.
- **Technical documentation:** Analyze drafts and improve accuracy, structure, and clarity.
- **Decision support:** Compare assumptions, alternatives, opportunities, and risks.
- **Educational workflows:** Explore competing explanations and reasoning approaches.
- **Prompt engineering:** Evaluate how different models respond to identical or customized instructions.

## Design Philosophy

AI Ping-Pong is built around three principles:

**Independence.** Models generate their initial responses independently, reducing direct influence between their first conclusions.

**User control.** The user manages every cross-model evaluation and determines the depth of the interaction.

**Transparency.** Responses and evaluation steps remain visible, allowing users to inspect the progression of the discussion.

The platform does not assume that agreement between AI models guarantees correctness. Instead, it provides a structured environment for comparing responses and identifying potential weaknesses.

## Основные возможности

### Параллельная обработка запросов

Пользователь вводит запрос в единое поле, после чего сервер одновременно направляет его двум независимо настроенным моделям.

Ответы отображаются в двух отдельных окнах, расположенных рядом.

Интерфейс поддерживает:

- Независимую потоковую генерацию ответов.
- Отображение состояния выполнения запросов.
- Измерение времени ответа с точностью до 0,1 секунды.
- Наглядное сравнение результатов.
- Независимый выбор моделей A и B.

Подключение внешних ИИ осуществляется через API-адаптеры, включая поддержку DeepSeek и OpenAI-совместимых интерфейсов.

### Управляемое взаимодействие моделей

Центральная функция AI Ping-Pong — передача ответов между моделями по инициативе пользователя.

**Model A → Model B**

Ответ модели A передаётся модели B для дальнейшей обработки.

**Model B → Model A**

Ответ модели B передаётся модели A.

При передаче сохраняются исходный запрос пользователя и необходимый контекст обсуждения.

В отличие от полностью автономных мультиагентных систем, AI Ping-Pong обеспечивает непосредственное управление процессом взаимодействия.

Пользователь определяет, какая модель будет оценивать другую, выбирает способ обработки информации и решает, когда завершить обсуждение.

### Четыре режима обработки

**Review — Рецензирование**

Принимающая модель проверяет полученный ответ, выявляет возможные фактические ошибки, логические противоречия, неполноту аргументации и предлагает улучшения.

**Analysis — Анализ**

Модель выполняет углублённый анализ переданного материала, исследует предположения, аргументацию, альтернативные решения и возможные последствия.

**Summary — Резюмирование**

Модель формирует структурированное краткое изложение полученного ответа, выделяя основные положения, выводы и значимую информацию.

**Custom Prompt — Пользовательская инструкция**

Пользователь самостоятельно задаёт инструкцию обработки через отдельное окно ввода.

Режим позволяет выполнять специализированные проверки, критический анализ, адаптацию текста, поиск недостатков и другие операции.

### Независимая настройка моделей

В боковом меню можно независимо выбирать модель для каждой из двух панелей.

Платформа предусматривает конфигурацию:

- Провайдера и модели A.
- Провайдера и модели B.
- Параметров подключения к API.
- Системных инструкций.
- Дополнительного контекста и внешних ресурсов.

Унифицированный интерфейс API-адаптеров позволяет подключать новые совместимые модели без изменения основной логики приложения.

### Дополнительный контекст и системные инструкции

Окно **Settings** предоставляет инструменты управления контекстом запросов.

**Add File or Image** — добавление документов и изображений в качестве дополнительной информации с учётом возможностей выбранной модели.

**Add Link** — подключение веб-ресурсов для контекстного анализа с использованием серверного механизма обработки ссылок.

**System Prompt** — настройка системных инструкций, определяющих поведение моделей, стиль ответов и особенности обработки запросов.

Эти инструменты позволяют адаптировать AI Ping-Pong для исследовательских, аналитических, инженерных и образовательных задач.

### Управление сессиями

AI Ping-Pong сохраняет структурированную историю взаимодействий, включающую:

- Исходные запросы пользователя.
- Независимые ответы моделей.
- Передачи сообщений между моделями.
- Выбранные режимы обработки.
- Результаты взаимных оценок.
- Время выполнения запросов.
- Конфигурацию сессии и связанный контекст.

Пользователь может создавать новые запросы и возвращаться к предыдущим сессиям через боковое меню.

История сохраняет последовательность взаимодействия, позволяя проследить развитие ответов после каждого раунда анализа.

Серверная часть управляет ключевыми процессами приложения:

- Передачей ответов между моделями.

Асинхронная архитектура обеспечивает одновременную обработку запросов без взаимной блокировки моделей.

**Прямое сетевое соединение между ИИ-провайдерами не требуется.** Обмен сообщениями координируется бэкендом AI Ping-Pong.

Обновление или замена контейнера не приводит к удалению сохранённых диалогов и конфигурационных данных.

Система безопасности предусматривает:

- Серверную аутентификацию API-запросов.
- Изоляцию секретов от браузера.
- Шифрование соединений по HTTPS/TLS.
- Ограниченный доступ к операциям управления ключами.
- Шифрование сохраняемых приватных данных.
- Разделение конфигурации приложения и секретов.
- Исключение приватных ключей из журналов событий.
- Проверку запросов и ограничения использования ресурсов.
- Управление разрешёнными API-подключениями.

Браузер обращается исключительно к серверной части AI Ping-Pong. Внешние API-запросы выполняются бэкендом с использованием авторизованных учётных данных.

## Логика работы

1. Пользователь выбирает модели A и B.
2. Вводит запрос в общее поле.
3. Бэкенд одновременно направляет запрос обеим моделям.
4. Ответы поступают в соответствующие окна.
5. Пользователь выбирает Review, Analysis, Summary или Custom Prompt.
6. Нажатием стрелки передаёт ответ одной модели другой.
7. Принимающая модель обрабатывает сообщение с учётом исходного запроса.
8. Новый ответ добавляется в историю соответствующей модели.
9. Пользователь продолжает взаимодействие или создаёт новую сессию.

Количество раундов определяется пользователем с учётом технических ограничений системы.

## Философия проекта

AI Ping-Pong основывается на трёх принципах.

**Независимость.** Модели первоначально формируют ответы самостоятельно, не влияя непосредственно на выводы друг друга.

**Управляемость.** Пользователь контролирует направление, режим и глубину взаимодействия.

**Прозрачность.** Результаты и этапы анализа доступны для изучения, что позволяет проследить изменение аргументации.

Согласие двух моделей само по себе не гарантирует правильности ответа. AI Ping-Pong предоставляет инструменты для содержательного сравнения, обнаружения недостатков и более глубокого исследования полученных результатов.

## Негізгі мүмкіндіктер

### Сұрауларды параллель өңдеу

Пайдаланушы ортақ енгізу өрісіне сұрау жазады. Сервер оны бір мезгілде екі тәуелсіз бапталған модельге жібереді.

Әр модель өз жауабын дербес қалыптастырады. Нәтижелер қатар орналасқан екі бөлек терезеде көрсетіледі.

Интерфейс мына мүмкіндіктерді қамтамасыз етеді:

- Жауаптарды тәуелсіз ағындық түрде шығару.
- Сұраулардың орындалу күйін көрсету.
- Жауап беру уақытын 0,1 секунд дәлдікпен өлшеу.
- Екі модель нәтижелерін қатар салыстыру.
- A және B модельдерін тәуелсіз таңдау.

Сыртқы жасанды интеллект модельдері API адаптерлері арқылы қосылады. Платформа DeepSeek және OpenAI-мен үйлесімді API интерфейстерін қолдайды.

### Модельдер арасындағы басқарылатын өзара әрекеттесу

AI Ping-Pong платформасының негізгі ерекшелігі — пайдаланушының шешімі бойынша жауаптарды бір модельден екіншісіне беру мүмкіндігі.

**Model A → Model B**

A моделінің жауабы қосымша өңдеу үшін B моделіне жіберіледі.

**Model B → Model A**

B моделінің жауабы A моделіне жіберіледі.

Ақпаратты беру кезінде пайдаланушының бастапқы сұрауы және талқылауға қажетті контекст сақталады.

Толық автономды көпагентті жүйелерден айырмашылығы, AI Ping-Pong өзара әрекеттесу процесін пайдаланушының тікелей басқаруына негізделген.

Пайдаланушы қай модельдің басқа модель жауабын бағалайтынын, қандай өңдеу әдісі қолданылатынын және талқылаудың қашан аяқталатынын өзі шешеді.

### Жауаптарды өңдеудің төрт режимі

**Review — Сыни бағалау**

Қабылдаушы модель берілген жауапты тексереді, ықтимал нақты қателерді, логикалық қайшылықтарды, дәлелдемелердің әлсіз тұстарын және жетіспейтін мәліметтерді анықтап, жақсарту жолдарын ұсынады.

**Analysis — Талдау**

Модель алынған материалға терең талдау жүргізеді, бастапқы болжамдарды, дәлелдерді, балама шешімдерді және ықтимал салдарларды қарастырады.

**Summary — Қысқаша қорытынды**

Модель бастапқы жауаптың негізгі ойларын, маңызды деректерін және қорытындыларын бөліп көрсететін құрылымдалған қысқаша мазмұн дайындайды.

**Custom Prompt — Пайдаланушы нұсқауы**

Пайдаланушы арнайы енгізу терезесі арқылы өңдеу нұсқауын өзі жазады.

Бұл режим мамандандырылған тексерулер, сыни талдау, мәтінді қайта өңдеу, кемшіліктерді анықтау және басқа да тапсырмалар үшін қолданылады.

### Модельдерді тәуелсіз баптау

Бүйірлік мәзір арқылы екі жұмыс панеліне арналған модельдер бөлек таңдалады.

Платформа келесі параметрлерді баптауға мүмкіндік береді:

- A моделінің провайдері мен нақты моделін.
- B моделінің провайдері мен нақты моделін.
- API қосылымдарының параметрлерін.
- Жүйелік нұсқауларды.
- Қосымша контекст пен сыртқы ресурстарды.

API адаптерлерінің бірыңғай интерфейсі қосымшаның негізгі логикасын өзгертпестен жаңа үйлесімді модельдерді қосуға мүмкіндік береді.

### Қосымша контекст және жүйелік нұсқаулар

**Settings** терезесінде модельдерге берілетін контексті басқару құралдары орналасқан.

**Add File or Image** — таңдалған модельдің мүмкіндіктеріне сәйкес құжаттар мен суреттерді қосымша ақпарат ретінде тіркеу.

**Add Link** — серверлік сілтеме өңдеу механизмі арқылы сыртқы веб-ресурстарды контекстік талдауға қосу.

**System Prompt** — модельдердің әрекетін, жауап беру стилін және сұрауларды өңдеу ерекшеліктерін анықтайтын жүйелік нұсқауларды баптау.

Бұл құралдар платформаны ғылыми-зерттеу, инженерлік, аналитикалық және білім беру міндеттеріне бейімдеуге мүмкіндік береді.

### Сессияларды басқару

AI Ping-Pong өзара әрекеттесудің құрылымдалған тарихын сақтайды.

Оған мыналар кіреді:

- Пайдаланушының бастапқы сұраулары.
- Модельдердің тәуелсіз жауаптары.
- Модельдер арасында жіберілген хабарламалар.
- Таңдалған өңдеу режимдері.
- Өзара бағалау нәтижелері.
- Сұраулардың орындалу уақыты.
- Сессия параметрлері мен тиісті контекст.

Пайдаланушы жаңа сұраулар жасап, бүйірлік мәзір арқылы бұрынғы сессияларға қайта орала алады.

Сақталған тарих әр талдау кезеңінен кейін жауаптардың қалай өзгергенін бақылауға мүмкіндік береді.

## Техникалық архитектура

AI Ping-Pong контейнерлік орналастыруға бейімделген модульдік клиент-сервер архитектурасына негізделген.

### Frontend

**React · TypeScript · Tailwind CSS · Vite**

Клиенттік бөлік екі жауап терезесі, модель таңдау элементтері, өңдеу режимдері, ақпарат беру батырмалары және сессияларды басқару құралдары бар интерактивті интерфейсті қамтамасыз етеді.

Компоненттік архитектура визуалды интерфейсті серверлік бизнес-логикадан бөледі.

Деректер HTTP API арқылы алмасады, ал жауаптардың ағындық берілуі Server-Sent Events (SSE) технологиясы арқылы жүзеге асырылады.

### Backend

**Python · FastAPI · AsyncIO**

Серверлік бөлік қосымшаның негізгі процестерін басқарады:

- Пайдаланушы сұрауларын өңдеу.

- Модельдер арасында жауаптарды бағыттау.
- Әңгімелесу контекстін қалыптастыру және сақтау.
- Таңдалған өңдеу режимдерін орындау.
- Жауаптарды ағындық түрде жеткізу.
- Сессияларды басқару.
- API провайдерлерін баптау.
- Құпия тіркелгі деректеріне қолжетімділікті басқару.
- Қателерді, шектеулерді және күту уақытын бақылау.

Асинхронды архитектура екі модельдің бір-біріне кедергі келтірмей, бір уақытта жұмыс істеуін қамтамасыз етеді.

### LLM интеграциялау қабаты

Интеграциялау қабаты сыртқы модель провайдерлеріне қосылудың бірыңғай механизмін ұсынады.

Әр провайдердің адаптері авторизацияға, сұрауларды қалыптастыруға, жауаптарды өңдеуге, ағындық генерацияға және API ерекшеліктеріне жауап береді.

Модельдер платформамен ресми HTTP API интерфейстері арқылы байланысады.

**Жасанды интеллект провайдерлері арасында тікелей желілік байланыс қажет емес.** Хабарламалар алмасуын AI Ping-Pong серверлік бөлігі үйлестіреді.

### Деректерді сақтау

**SQLite · Docker тұрақты томдары**

Сессиялар тарихы мен қосымша деректері контейнердің жұмыс істеу мерзімінен тәуелсіз тұрақты сақтау жүйесінде орналасады.

Контейнерді жаңарту немесе ауыстыру сақталған әңгімелер мен конфигурация деректерінің жоғалуына әкелмейді.

AI Ping-Pong архитектурасы құпия тіркелгі деректерін сервер жағында өңдеуге және оларды браузерде орындалатын кодтан оқшаулауға негізделген.

Қауіпсіздік шаралары мыналарды қамтиды:

Браузер тек AI Ping-Pong серверімен байланысады. Сыртқы LLM API сұрауларын сервер авторизацияланған тіркелгі деректерін пайдаланып орындайды.

## Қолдану салалары

- **Жасанды интеллект жауаптарын тексеру:** тәуелсіз нәтижелерді салыстыру және өзара сыни бағалау.
- **Ғылыми-зерттеу жұмыстары:** күрделі мәселелерді әртүрлі модельдердің көзқарасы бойынша қарастыру.
- **Бағдарламалық жасақтама әзірлеу:** архитектураны, кодты және техникалық шешімдерді талдау.
- **Техникалық құжаттама:** материалдардың толықтығын, құрылымын және дәлдігін тексеру.
- **Шешім қабылдауды қолдау:** баламаларды, болжамдарды және тәуекелдерді зерттеу.
- **Білім беру:** әртүрлі түсіндірулер мен есеп шығару тәсілдерін салыстыру.
- **Prompt Engineering:** бірдей және арнайы нұсқауларға әртүрлі модельдердің жауап беру ерекшеліктерін зерттеу.

## Жобаның негізгі қағидаттары

AI Ping-Pong үш негізгі қағидатқа сүйенеді.

**Тәуелсіздік.** Модельдер бастапқы жауаптарын бір-бірінің қорытындыларына тікелей әсер етпей қалыптастырады.

**Басқару мүмкіндігі.** Пайдаланушы өзара әрекеттесудің бағытын, режимін және тереңдігін өзі анықтайды.

**Ашықтық.** Талдау кезеңдері мен нәтижелері пайдаланушыға көрініп тұрады, бұл дәлелдердің қалай өзгеретінін бақылауға мүмкіндік береді.

Екі модельдің бір пікірге келуі жауаптың міндетті түрде дұрыс екенін білдірмейді. AI Ping-Pong нәтижелерді мазмұнды салыстыруға, әлсіз тұстарды анықтауға және ақпаратты тереңірек зерттеуге арналған құралдарды ұсынады.
